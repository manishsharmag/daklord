This document describes everything needed to build, sign, and ship the **Insta Reel Downloader** Flutter/Android app from VS Code, including native binary bring-up (yt-dlp/FFmpeg/ESRGAN), required environment variables, and the Play Store submission checklist. Follow it end-to-end to produce a release-signed APK/AAB and submit it to Google Play without additional guidance.

## Toolchain Setup in VS Code
The project targets **Flutter 3.13+ (Dart 3.11)**, Android **compileSdk 34**, **minSdk 24**, and uses Kotlin + native binaries. Install the following on macOS, Linux, or Windows.

### 1. Install system prerequisites
| Component | Version | Notes |
| --- | --- | --- |
| Flutter SDK | 3.13 or newer | `flutter upgrade` if needed. The repo targets Dart SDK `^3.11.0-158.0.dev`.
| Java | JDK 17 (Temurin, Zulu, or Android Studio JDK) | Required by Gradle & Kotlin.
| Android SDK | API 34 (Android 14), Build Tools 34.0.0 | Install via `sdkmanager` or Android Studio.
| Android NDK | Version reported by `flutter doctor` (currently 25.2+) | Needed because the project bundles JNI libs for yt-dlp/FFmpeg.
| VS Code | Latest stable | With Flutter + Dart extensions.
| Android Studio (optional) | Flamingo or newer | Provides SDK Manager & Platform Tools even if VS Code is used for coding.
| Platform Tools | `adb`, `fastboot` | Install via `sdkmanager "platform-tools"`.

### 2. Configure Flutter & VS Code
1. **Download Flutter** and add it to your PATH:
   ```bash
   export FLUTTER_HOME=$HOME/tools/flutter
   export PATH="$FLUTTER_HOME/bin:$PATH"
   flutter doctor
   ```
2. **Install VS Code extensions**: `Flutter`, `Dart`, and (optional) `Android i18n`.
3. **Enable the Flutter daemon**: `View → Command Palette → Flutter: Run Flutter Doctor`. Resolve any issues before continuing.

### 3. Android toolchain steps
1. Install required SDK components:
   ```bash
   sdkmanager "platforms;android-34" "build-tools;34.0.0" "platform-tools" "cmdline-tools;latest" "ndk;25.2.9519653"
   ```
2. Set `ANDROID_HOME`/`ANDROID_SDK_ROOT` to the SDK path and add `platform-tools` to PATH.
3. Accept all licenses:
   ```bash
   flutter config --android-sdk $ANDROID_HOME
   flutter doctor --android-licenses
   ```
4. Create or configure a device:
   - **Physical device**: enable USB debugging and run `adb devices`.
   - **Android Emulator**: create a Pixel 6+ running API 34 via `avdmanager` or Android Studio. Launch it before running VS Code.

### 4. Prepare VS Code workspace
1. `File → Open Folder…` and select `/home/engine/project` (or your local clone).
2. The `.vscode/launch.json` is auto-generated by Flutter. Use the Run and Debug panel to select **`insta_reel_downloader`**.
3. Use the VS Code terminal (`` Ctrl+` ``) for all commands described below to keep the IDE context consistent.

## Required Environment Variables & Secrets
Configure these variables in your shell profile (macOS/Linux) or System Environment settings (Windows). Add them to CI/CD secrets if applicable.

| Variable | Purpose | Example |
| --- | --- | --- |
| `FLUTTER_HOME` | Root of Flutter SDK. | `/Users/dev/tools/flutter` |
| `ANDROID_HOME` / `ANDROID_SDK_ROOT` | Android SDK installation. | `/Users/dev/Library/Android/sdk` |
| `JAVA_HOME` | JDK 17 path. | `/Library/Java/JavaVirtualMachines/temurin-17.jdk/Contents/Home` |
| `GRADLE_USER_HOME` (optional) | Custom Gradle cache location (avoids permissions issues). | `$HOME/.gradle` |
| `PATH` | Must include `$FLUTTER_HOME/bin`, `$ANDROID_HOME/platform-tools`, `$ANDROID_HOME/emulator`. | `export PATH="$FLUTTER_HOME/bin:$ANDROID_HOME/platform-tools:$PATH"` |

### App-specific secrets
Keep signing secrets out of source control.

| Variable | Description |
| --- | --- |
| `KEYSTORE_PATH` | Absolute path to your release keystore (e.g., `$HOME/.keystores/insta-reel.jks`). |
| `KEYSTORE_PASSWORD` | Store password. |
| `KEY_ALIAS` | Alias created when generating the keystore. |
| `KEY_PASSWORD` | Alias password (can match store password). |

> Store these values in a secure secrets manager. When working locally, export them in your shell or `.zshrc` and **never commit** the keystore.

### `key.properties`
Create `android/key.properties` (ignored by Git) and reference your environment variables:
```properties
storeFile=/Users/dev/.keystores/insta-reel.jks
storePassword=${KEYSTORE_PASSWORD}
keyAlias=${KEY_ALIAS}
keyPassword=${KEY_PASSWORD}
```
Alternatively, load them dynamically in `build.gradle.kts`:
```kotlin
val keystoreProperties = Properties().apply {
    val file = rootProject.file("key.properties")
    if (file.exists()) file.inputStream().use(::load)
}

android {
    signingConfigs {
        create("release") {
            storeFile = keystoreProperties["storeFile"]?.let { file(it as String) }
            storePassword = keystoreProperties["storePassword"] as String?
            keyAlias = keystoreProperties["keyAlias"] as String?
            keyPassword = keystoreProperties["keyPassword"] as String?
        }
    }
    buildTypes {
        getByName("release") {
            signingConfig = signingConfigs.getByName("release")
            isMinifyEnabled = false
        }
    }
}
```

### `local.properties`
Flutter auto-generates `android/local.properties` with `sdk.dir`, `flutter.sdk`, and `flutter.buildMode`. Confirm it points to your SDK before building release artifacts, especially on CI.

## Flutter & Gradle Build Workflows
All commands are run from the repo root (`/home/engine/project`). When using VS Code, run them from the integrated terminal so the IDE stays aware of build outputs.

### 1. Debug builds (APK)
**VS Code UI:**
1. Click **Run and Debug** (⌘⇧D / Ctrl+Shift+D).
2. Select the target device.
3. Choose **`Flutter` → `Run`** to deploy a debug build.

**Equivalent CLI:**
```bash
flutter pub get
flutter run --debug --device-id <device_id>
```
- Produces an unsigned debug APK streamed directly to the device.

### 2. Release APK builds (Play Store-compliant)
```bash
# Build universal release APK (signed when signingConfig.release is set)
flutter build apk --release \
  --dart-define=BUILD_FLAVOR=playstore \
  --split-per-abi # optional but recommended for Play optimizations
```
Artifacts are written to `build/app/outputs/flutter-apk/`:
- `app-release.apk` (universal)
- `app-arm64-v8a-release.apk`, etc., when `--split-per-abi` is used.

### 3. App Bundle builds (required for Play Console)
```bash
flutter build appbundle --release \
  --dart-define=BUILD_FLAVOR=playstore \
  --obfuscate --split-debug-info=build/debug-info
```
- Outputs `build/app/outputs/bundle/release/app-release.aab`.
- The `--split-debug-info` directory must be archived securely for future symbolication.

### 4. Gradle command equivalents
Use Gradle when you need fine-grained control (CI, Play publishing API, custom build variants).
```bash
cd android
./gradlew clean
./gradlew assembleDebug           # Debug APK
./gradlew assembleRelease          # Release APK
./gradlew bundleRelease            # App Bundle
./gradlew signingReport            # Inspect SHA1/SHA256
./gradlew lintVitalRelease         # Play Store lint check
```
> Ensure `JAVA_HOME` points to JDK 17 before invoking Gradle.

### 5. Build variants for the Play Store
While the project currently ships a single variant, follow these guidelines for compliance:
1. **Application ID** – Update `applicationId` in `android/app/build.gradle.kts` from `com.example...` to your production ID (e.g., `com.yourcompany.instareel`).
2. **ABI coverage** – Keep `armeabi-v7a`, `arm64-v8a`, and `x86_64` enabled (already configured via `ndk { abiFilters }`).
3. **Target API** – Align `compileSdk` and `targetSdk` with the latest stable API (34 as of 2024). Flutter manages this via `flutter.compileSdkVersion`/`flutter.targetSdkVersion`.
4. **Versioning** – Update `pubspec.yaml` (`version: x.y.z+build`) before each submission. `versionName`/`versionCode` are derived from here.
5. **Code shrinker** – Optionally enable R8 by setting `isMinifyEnabled = true` with proper ProGuard rules once binaries are finalized.

## Android App Signing

### 1. Generate a keystore (one-time)
```bash
keytool -genkeypair \
  -alias instaReel \
  -keyalg RSA -keysize 4096 -validity 3650 \
  -storepass "<STORE_PASSWORD>" \
  -keypass "<KEY_PASSWORD>" \
  -keystore $HOME/.keystores/insta-reel.jks \
  -dname "CN=Insta Reel Downloader, O=Your Company, C=US"
```
- Keep the `.jks` outside the repo.
- Back it up in a secure vault (e.g., 1Password, Google Secret Manager).

### 2. Wire the keystore into Gradle
1. Create `android/key.properties` referencing the keystore paths/passwords.
2. Update `android/app/build.gradle.kts` to load the file and set `signingConfigs.release` (example snippet provided above).
3. Verify signing works:
   ```bash
   cd android
   ./gradlew signingReport
   ```
   Capture the SHA-1/SHA-256 fingerprints for Play Console and Firebase.

### 3. VS Code integration
- Once the signing config is in place, VS Code builds (`flutter build apk --release`) automatically use it.
- Use the **Flutter: Select Device** command to push the signed APK to a test device for smoke testing before uploading.

## Native Binary Bring-Up (yt-dlp, FFmpeg, Real-ESRGAN)
The app offloads downloading & processing to native binaries managed by `BinaryBootstrapper` (see `DownloaderBridge.kt` and `UpscalerBridge.kt`). Understanding their lifecycle is essential for QA and release readiness.

### 1. Asset locations
| Component | Location | Notes |
| --- | --- | --- |
| yt-dlp bridge | `android/app/src/main/jniLibs/<abi>/libytdlp_bridge.so` | Native wrapper that drops a `yt-dlp` executable at runtime.
| FFmpeg bridge | `android/app/src/main/jniLibs/<abi>/libffmpeg_bridge.so` | Provides FFmpeg binary with the required codecs.
| Stub fallbacks | `android/app/src/main/assets/downloader/yt-dlp.stub` & `ffmpeg.stub` | Simple shell scripts used when ABI-specific binaries are missing. Replace with production binaries.
| Real-ESRGAN model | `android/app/src/main/assets/upscaler/esrgan_fp16.tflite` | Not bundled by default—add your converted model here.

### 2. How BinaryBootstrapper works
1. On first launch, it looks for the ABI-matching `.so` inside `jniLibs`.
2. The `.so` contains the actual binary payload; it is extracted to `files/native-binaries/<name>`.
3. Executables are marked with `chmod +x` and reused for subsequent runs.

### 3. Running binaries on a device/emulator
Run the app once so the binaries are extracted, then execute them via `adb`:
```bash
adb shell run-as com.example.insta_reel_downloader ls files/native-binaries
adb shell run-as com.example.insta_reel_downloader ./files/native-binaries/yt-dlp --version
adb shell run-as com.example.insta_reel_downloader ./files/native-binaries/ffmpeg -hide_banner -codecs | head -n 20
```
> Replace `com.example...` with your final `applicationId`.

### 4. Supplying production binaries
1. Drop architecture-specific binaries into `android/app/src/main/jniLibs/<abi>/` and name them according to `BinaryAsset` (`libytdlp_bridge.so`, `libffmpeg_bridge.so`).
2. Alternatively, update the stub shell scripts to download and unpack upstream releases during bootstrap (ensure licenses allow redistribution).
3. Rebuild the APK to embed the binaries. Verify sizes stay within Play Store limits.

### 5. Testing yt-dlp end-to-end
1. Connect a device with network access.
2. Run:
   ```bash
   adb shell run-as <applicationId> ./files/native-binaries/yt-dlp --dump-json https://www.instagram.com/reel/<ID>/
   ```
3. Confirm the JSON metadata is returned within ~8 seconds (the Kotlin wrapper enforces the timeout).
4. Review logs:
   ```bash
   adb logcat -s DownloaderBridge YtDlp
   ```

### 6. Testing FFmpeg
1. Push a short MP4 to the app sandbox:
   ```bash
   adb push sample.mp4 /sdcard/Download/
   ```
2. Use the `Downloads` tab in the app to enqueue and finalize a download. FFmpeg remuxing occurs automatically—check `adb logcat | grep FFmpeg` for success/failure.
3. Manual CLI test:
   ```bash
   adb shell run-as <applicationId> ./files/native-binaries/ffmpeg -i /sdcard/Download/sample.mp4 -f null -
   ```

### 7. Running Real-ESRGAN locally
1. Convert or download a TFLite FP16 model (see `UPSCALING.md`).
2. Place it at `android/app/src/main/assets/upscaler/esrgan_fp16.tflite`.
3. Rebuild the app, then monitor logs while triggering an upscale:
   ```bash
   adb logcat | grep -i "UpscalerBridge"
   ```
4. To validate GPU/NNAPI delegate usage, look for `GpuDelegate` or `NnApiDelegate` logs. If absent, the code falls back to bicubic scaling (`simulateUpscale`).

### 8. Desktop testing of binaries (optional)
For CI or local reproducibility, run the same commands using the standalone binaries on your workstation:
```bash
./native-tools/yt-dlp --dump-json <url>
./native-tools/ffmpeg -i input.mp4 -vf "fps=30" frames/frame_%04d.png
python tools/run_esrgan.py --model esrgan_fp16.tflite --input frame_0001.png --scale 2
```
Keep host binaries in sync with the in-app versions to match behavior.

## Verifying the No-Backend Architecture
The Insta Reel Downloader intentionally avoids proprietary backend services; everything happens on-device:
- **URL validation & metadata** – `DownloaderBridge` uses `yt-dlp` locally. No custom API calls.
- **Downloads** – The Kotlin pipeline writes to `getExternalFilesDir(Environment.DIRECTORY_MOVIES)` without cloud relays.
- **Upscaling** – `UpscalerBridge` processes frames via FFmpeg + TFLite entirely offline.

### 1. Code inspection
- Review `android/app/src/main/kotlin/.../DownloaderBridge.kt` – only Instagram URLs plus native binaries are touched.
- Review `android/app/src/main/kotlin/.../UpscalerBridge.kt` – progress events originate from local tasks.

### 2. Runtime verification steps
1. **Network proxy inspection** – Route the device through Charles/mitmproxy and record traffic while downloading + upscaling:
   - You should see requests only to `instagram.com`, `cdninstagram.com`, or `fbcdn.net` (as initiated by yt-dlp), plus standard Google Play services. No custom domains should appear.
2. **Offline upscaling** – Put the device in Airplane Mode *after* a reel has been downloaded and stored in `Downloads`. Trigger an upscale:
   - Expected: Upscaling completes successfully since it touches only local files and the bundled model/binaries.
3. **adb traffic stats** – Confirm no sockets stay open during upscaling:
   ```bash
   adb shell dumpsys connectivity | grep -i insta
   adb shell cat /proc/net/tcp | grep :
   ```
4. **Logging** – `adb logcat | grep -i BinaryBootstrapper` shows when binaries are extracted locally.

Documenting the test results (screenshots/logs) satisfies internal audits that no backend exists.

## Play Store Submission Checklist
Use this list every release to keep submissions consistent.

### Pre-build
- [ ] Update `pubspec.yaml` version (`x.y.z+build`).
- [ ] Update changelog/release notes.
- [ ] Ensure `applicationId` is final (no `com.example`).
- [ ] Run `flutter test` / smoke tests on physical devices (minimum: API 24, API 34, and one x86_64 emulator).
- [ ] Verify yt-dlp/FFmpeg binaries include licenses compatible with Play (e.g., GPL compliance documentation).

### Build artifacts
- [ ] `flutter build appbundle --release --obfuscate --split-debug-info=build/debug-info`.
- [ ] (Optional) `flutter build apk --release --split-per-abi` for sideload/internal QA.
- [ ] Archive `build/app/outputs/` plus `build/debug-info` into your release bundle for traceability.

### Privacy policy & Data safety
**Suggested privacy policy snippet** (host it on your company domain and reference it in the Play Console):
> Insta Reel Downloader processes Instagram reel links entirely on-device. The app does not collect, store, or transmit personal data to our servers. Downloads and upscaling use bundled binaries (yt-dlp, FFmpeg, Real-ESRGAN) and save output only to the users device storage. No analytics, advertising, or tracking SDKs are included.

In the **Data Safety** form:
- Data collection: **No**.
- Data sharing: **No**.
- Encryption: **Not applicable** (all processing local).
- Data deletion: **All data remains on device; uninstall removes it**.

### Content rating questionnaire (recommended responses)
- Violence, sexual content, profanity: **No** (app processes user-provided content only).
- User-Generated Content: **Users supply URLs; no sharing or community features**.
- Messaging, user-to-user interaction: **No**.
- Gambling, contests, in-app purchases: **No**.

### Graphic assets
- **Feature graphic**: 1024 x 500 px, PNG or JPG, <1 MB.
- **Phone screenshots**: At least 2 (1080x2400 recommended) showing Home, Downloads, and Upscaling progress.
- **7" & 10" tablet screenshots**: Optional but recommended.
- **App icon**: 512 x 512 px, 32-bit PNG, <1024 KB.

### Testing instructions for reviewers
Provide the following text in the Play Console "App access" / "Testing instructions" fields:
1. Open the app Home tab.
2. Paste any public Instagram reel URL (no login required) and tap **Download**.
3. Wait for the item to appear under **Downloads → History**.
4. Tap **Upscale**, select 2x, and observe progress.
5. Verify the upscaled file appears inside `Android/data/<applicationId>/files/Movies/<reel_id>/` (or share via system picker).
6. Optional: Toggle Airplane Mode after downloading and repeat the upscale to confirm offline behavior.

### Submission steps
- [ ] Upload the `.aab` to the desired track (Internal > Closed > Production).
- [ ] Attach release notes (list new features, binary updates, ESRGAN improvements).
- [ ] Fill in the content rating, privacy policy URL, and Data Safety responses.
- [ ] Provide tester emails (internal testing) and opt them in.

- [ ] Monitor **Android Vitals** and **ANR/Crash** dashboards after rollout.

## Troubleshooting & References
| Scenario | Diagnostic steps |
| --- | --- |
| VS Code cant detect device | Run `adb devices`, ensure USB debugging enabled, restart `adb kill-server && adb start-server`. |
| NDK missing error | Install the required version via `sdkmanager "ndk;25.2.9519653"` and re-run `flutter doctor`. |
| Signing fails (`No key with alias`) | Verify `key.properties` paths, re-run `./gradlew signingReport`, ensure environment variables exported in VS Code terminal. |
| yt-dlp timeout | Increase timeout in `YtDlpMetadataExtractor` (if needed) or test connectivity to `instagram.com`. |
| FFmpeg crashes on certain reels | Check `adb logcat -s FFmpeg` for codec support, ensure the bundled binary includes `libx264` and `aac`. |
| Upscaling stuck at 20% | Usually indicates GPU delegate failure. Confirm `esrgan_fp16.tflite` exists and matches the expected input shape, or fall back to bicubic. |
